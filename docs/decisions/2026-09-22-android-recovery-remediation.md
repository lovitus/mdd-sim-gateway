## 1. 完整交付范围

### 用户需求与来源

用户要求的是能实际使用的原生 Android 客户端，不是只有后台连接或诊断状态的演示程序。
本轮用户明确要求：开发计划记录具体需求，并给出优雅、可交互的页面设计，防止后台实现脱离操作。
以下功能目标来自 PR #7 的 Android 决策和交付材料，是本次评审的产品基线；不是本轮新增授权。
下面的布局、按钮和文案是本方案提出的设计，不冒称用户逐项指定。

| 需求 | 用户能够完成的事情 | 本批交付边界 |
|---|---|---|
| 方便接入网关 | 登录、扫码/粘贴设置、自签证书指纹确认；再次打开不反复配置 | 保留现有入口；补存储失败和会话过期的明确恢复入口 |
| 分享外接读卡器 | 对具体 USB 设备授权，看到当前卡片身份与共享状态，主动启停共享 | 补换卡、暂停后恢复及旧观察失效，不能显示旧卡已就绪 |
| 服务器线路通话 | 选择 SIM 和通道，拨打、接听、拒接、静音、扬声器、DTMF、挂断 | 保留原流程；进程死亡后仍能核对和结束原通话 |
| 服务器短信 | 选择线路/通道，发送一次、查看最近消息，知道发送结果是否确定 | 保留流程和未知记录，不因重连、重启或读取异常重复发送 |
| 长连接与不稳定网络 | 主动选择保持可用或暂停；断网后知道在恢复什么 | 连接恢复不冒充业务恢复，不自动重拨、不改变用户开关 |
| 易用与可信状态 | 中文页面、明确线路身份、状态与动作一致，错误时有可操作下一步 | 不用技术日志充当页面，不以设备在线冒充 IMS/语音就绪 |
| 隐私及收费安全 | 操作前看清号码/线路/通道，未知结果不被清空，通知不泄露正文 | 不新增实际付费验收或 SIM 操作授权 |

Android 原生界面使用 Java/Android 组件不等于恢复旧 Python/VPCD 后端；核心业务继续复用 Go。
手机自带 SIM 的系统拨号与服务器通话必须明确区分；USB 读卡器本身不提供蜂窝射频。
Windows/macOS/Linux 远程 Agent 和开启 4G 的强制隔离要求保持不变，本批不调整桌面产品范围。

### 用户主流程完成条件

用户再次打开 App 时，应首先看到自己仍在处理的事情：正常则进入上次页面；有未决通话则
看到恢复入口；存储暂时读不到则保留原配置并提供重试。不能一律回到像首次安装一样的空白登录页。
关闭共享后换卡，再打开共享，应看到重新检测，随后只出现新卡；未知通话不能凭空消失。
发出挂断后，界面必须区分本地声音停止、远端结束未确认、远端已确认结束。

一次修复同一恢复主流程的四个缺口：

1. 读取配置失败不得删除配置、凭据和未知操作记录。
2. 读卡器重新共享/重新连接不得把过期拓扑当作当前就绪状态。
3. App 进程死亡后，恢复原未决通话的核对和授权挂断入口，不重新拨号。
4. 正常挂断与恢复挂断统一终态判断，不能把 HTTP 200、404 或媒体关闭当作已确认结束。

存储、读卡器、Android/Core 接口、页面和回归属于同一整改批次。先全部实现，再集中验证，
最后一个交付提交更新 PR #7；不按单类、单接口、单测试拆分微提交。PR 保持 draft 待评审。

不在范围：替换整套 Android UI 框架、恢复 VPCD、自动重拨/SMS、跨进程自动开麦、生产部署、真实
收费业务、SIM 变更、eSIM 删除、桌面 4G 开关调整、FCM 接入或全天候后台送达承诺。
真实读卡器兼容性、Doze/耗电、运营商验收与长期签名是独立事项，不冒称随本批完成。

## 1A. 页面与交互设计

### 布局与复用组件

沿用原生五页：首页、通话、短信、读卡器、设置。底部导航使用图标加短标签，不用五个
挤在顶部的普通命令按钮；保留现有 Activity/Service 边界，不为此引入新 UI 框架。
顶部只保留页面标题、网关简称和连接状态。正文采用列表、分组标题和细分隔线，不把每段内容
都放进卡片。活动通话是需要持续可见的独立控制区域，不随切换 tab 销毁。

统一复用：连接状态条、线路选择器、状态行、当前通话条、错误恢复面板、确认对话框。
中文为完整可用语言，沿用系统语言/现有资源选择；原始错误码收进可展开详情，不把英文异常堆在首页。
状态不能仅靠红绿区分：文字加图标，明确连接、设备、IMS、通话分别是什么状态。
图标使用项目可用的标准 Android 图标资源，提供无障碍名称；不手绘含糊图标或引入整套新设计依赖。

布局约束：320dp 窄屏、横屏、200% 字体、系统栏和软键盘下都可操作。控件触控目标至少
48dp；文本允许换行但不得遮挡按钮。拨号键盘稳定三列，导航和底部操作不被键盘盖住。
后台更新按稳定 ID 更新行，不重建整个页面，不重置所选线路、通道、号码、短信草稿或滚动位置。
所选线路消失、换卡或不可用时，保留原选择并标记不可用，要求用户重新选择；禁止自动选择
第一条剩余线路或切换通道。确认框捕获不可变的线路、卡片、通道、号码及必要 occurrence，
提交前重新校验同一意图。期间身份变化则零派发、保留输入，显示“线路身份已变化，请重新选择”。
旋转/Activity 重建保留当前页面和表单；进程重启只保证本批耐久业务记录，不新增长期短信草稿存储。

### 页面信息与动作

| 页面 | 常态展示 | 主要交互和异常态 |
|---|---|---|
| 首页 | 网关连接、保持可用开关、线路摘要、读卡器共享摘要 | 存储/登录/恢复问题显示一个对应行动入口；不展示大段架构说明 |
| 通话 | 当前线路名称、可用电话号码和卡尾号；VoWiFi/蜂窝通道；号码输入及拨号键盘 | 拨打前确认精确线路/通道/号码；来电显示线路、主叫、接听和拒接；通道不可用给实际原因 |
| 短信 | 线路/通道选择、最近消息列表、收件人和编辑区 | 保留最近 50 条边界；发送中禁重复提交；结果未知保留查看记录入口，不出现一键自动重发 |
| 读卡器 | 共享总开关，逐设备权限、连接、当前卡尾号、SIM 识别状态 | 针对具体设备授权；扫描中显示检测中；暂停显示未共享，旧卡只可标为历史信息 |
| 设置 | 网关、当前账户、证书信任状态、版本、通知和系统电源设置入口 | 重新登录、退出、脱敏诊断；清除本地数据放危险操作区，不作为读取失败的首选动作 |

电话号码只显示服务端实际提供的值，不从名称或 ICCID 推断；没有号码明确显示未获取。
若现有 mobile feed 缺电话号码，只复用现有目录已知字段做窄展示适配，不触发读卡/运营商查询。
线路选择器可以展开查看完整身份，行数超出 128 或快照不完整必须可见，不能伪装全部已加载。
拨号键盘提供独立可触达的 `+` 操作，数字、`*`、`#`、删除都有对应按钮；不是只能靠软键盘输入国家码。
服务端拨号为主操作；“用手机拨号”是独立次级入口，不能暗中切换到手机 SIM。
与当前整改无关的录音、余额查询、eSIM 管理和新管理页面不加入本批。

### 通话页线框与跨页控制

```text
通话                              网关已连接
英国线路  +44…  · 卡尾号 4080             >
通道  [VoWiFi] [蜂窝模块]
--------------------------------------------
                  +44…                 删除
             1        2        3
             4        5        6
             7        8        9
             *        0        #
             +          拨打
用手机拨号
--------------------------------------------
首页      通话      短信      读卡器      设置
```

示意中的号码是占位，不是测试目标。通话开始后号码输入区替换为主叫/被叫、线路/通道、真实
状态及静音、扬声器、DTMF、挂断。未确认接通不显示已接通计时；恢复记录没有可信接通时间
则不编造时长。切换页面显示紧凑通话条，点击回到通话页，保留直接挂断入口。
进程重建后恢复条明确显示“待核对的通话”，不伪装为正在通话；恢复控制时麦克风保持关闭。

### 恢复状态到页面动作的契约

| 状态 | 用户看到 | 可以做什么 | 不允许做什么 |
|---|---|---|---|
| 首次安装且确无数据 | 设置网关 | 输入或扫码，确认后登录 | 把读取异常当首次安装 |
| 保存数据暂不可读 | “暂时无法读取已保存设置，数据未删除” | 重试、查看详情；若内存仍有已知通话，保留授权挂断 | 自动清空、直接显示空登录表单、新拨号/短信 |
| 已保存格式较新或不可解密 | 明确兼容/读取错误 | 查看详情、重试、进入设置中的显式重置 | 隐式降级覆盖，谎称只需重新登录即可恢复 |
| 会话过期且有未决通话 | “请登录原账户以核对上次通话” | 原网关重新认证 | 丢弃记录、跨账户接管 |
| 正在核对原通话 | 原线路/号码（若已知）、状态核对中 | 返回其他页面；保留恢复条 | 新拨号、自动开麦、重复核对并发请求 |
| 原通话活动且可控制 | “上次通话仍在进行，麦克风未开启” | 挂断、查看精确状态 | 自动重拨或假装音频恢复 |
| 结束请求已发送未确证 | “声音已停止，远端结束尚未确认” | 核对状态；满足原幂等契约后明确重试结束 | 显示已挂断、清空记录 |
| 服务器离线或结果未知 | “暂时无法确认上次通话状态” | 网络恢复后的有界核对、手动重试 | 一直转圈、无限自动轮询或新拨号 |
| 身份/所有权不匹配 | 明确是哪类身份冲突，细节按需展开 | 返回正确网关/账户、查看详情 | 接管其他可见活动通话 |
| 权威终态已保存 | “通话已结束”或真实失败结论 | 返回拨号；不再占用跨页控制条 | 以 HTTP 成功替代终态 |
| 远端终态已确认但本地保存失败 | “通话已在远端结束，但恢复状态保存失败” | 重试保存/核对，保留存储告警 | 再次自动挂断、删除耐久未决记录、绕过存储门禁 |
| 当前证据不足以自动核对 | “需要在网关核对上次通话”及缺失证据类别 | 打开已有网关管理入口、查看脱敏详情 | 用重置/超时冒充通话结束 |

初次恢复自动进行一次精确核对；失败后结束忙态并显示操作入口。网络事件触发的核对复用
同一个在途请求和有界退避，不在 UI render 中发请求，不把每次页面刷新变成状态查询。
手动重试进行中禁重复点击，完成后恢复按钮；不新增后台永久恢复守护程序。
未知通话只阻止该 App 的新通话；短信仅按自身存储/会话/服务端门禁判断，不能无故禁用整个 App。

### 对话框与用户开关

同一原生确认组件用于拨号、短信提交、重置和账户切换，展示目标与后果，不用含糊的“确定？”
代替意图确认。系统 USB、相机、麦克风权限仍使用 Android 系统权限框，不绕开权限机制。
正常挂断是直接安全动作，不增加确认层妨碍停止计费；状态未知时的再次结束必须明确标注为
处理同一通话，不暗中创建新操作。退出/重置不得冒充远端挂断。
用户改变保持可用/共享开关时，若原通话占用禁止切换，开关留在原值并显示原因，不能先变色
再偷偷恢复。断网不等于用户关闭共享；用户关闭共享也不能被自动恢复逻辑重新打开。

### 按用户动作验收页面

| 用户操作 | 页面验收与业务证据 |
|---|---|
| 首次登录、退出重开、读取失败后重试 | 首次安装与故障页面不同；原设置保留；重试不丢表单、不重复登录 |
| 拨号输入国际号码、取消确认、确认一次 | `+` 可点；确认显示准确线路和通道；取消零派发，确认至多一次 |
| 发送短信时网络丢失、旋转或重开 | 未知记录仍可见，无隐式重发，不清空为已成功 |
| 来电时切页、接听/拒接 | 跨页入口仍可用、沿用原 call ID；不启动第二通话所有者 |
| 共享关闭、换卡、重新共享 | 先检测中再显示当前卡，列表和详情一致，不闪回旧卡就绪 |
| 通话中杀进程、重开、核对、挂断 | 恢复条/按钮真实可点，未自动开麦，远端只有原通话，确证后才消失 |
| 挂断返回 false、404、超时 | 显示未确认；本地音频关闭；记录和核对入口保留 |
| 窄屏、大字体、横屏、键盘弹出及状态刷新 | 无遮挡，号码/草稿/选项不跳动，挂断和确认按钮可触达 |

在 GitHub Android 模拟器用 UI 自动化实际点击上述主流程，保存关键状态截图和操作/请求
证据；不能用直接调用 Service 方法或只截登录页冒充页面验收。真实手机/运营商仍单独标未验。

## 3. 存储实现

### 最小改动与单一所有者

优先验证现有加密 SharedPreferences 是否满足下述故障契约；不预先认定它必然足够。
建立应用级唯一存储入口，Activity/Service
都通过该入口更新字段，不能各自读整份 JSON 后覆盖其他并发写入。
现有 synchronized 仅保护单个 ConfigStore 实例，不等于应用级串行化。

每次更新基于最新已提交记录生成副本，串行加密并同步 commit；确认成功后才发布内存新状态。
写失败不发送新的 start/answer/SMS，不用未提交内存状态冒充耐久记录。
若底层写失败可能影响内存缓存，进入存储故障状态，禁止随后基于该缓存继续覆盖。
不为本批预先改用新文件、数据库或引入通用事务框架。

### 真实缺失、写入不确定及恢复门槛

SharedPreferences 部分容器读取/解析失败可能返回空映射；`getString` 默认空值、contains=false
或重新创建包装类都不能证明首次安装。必须在跨进程测试中覆盖实际 preferences 容器损坏，
而不只是合法 XML 中的坏密文。首次初始化须有可靠的存储缺失证据；已有容器/备份或读取
不确定时保持故障态，不写入空配置。不能以同一个可能丢失的 preferences 标记自证不存在。

commit 返回 false、中断或进程死亡时，不假定旧值或尝试值已耐久。当前进程锁定写入门禁，
停止设置、登录和操作记录的后续覆盖，保留原材料与在途记录身份。不得通过同进程缓存读回
解除门禁。解除须先确保旧写入不再在途，再从可靠磁盘读取验证加密完整性、schema、记录
revision 和阶段一致性；若不能证明得到的是可信记录，保持故障，不允许盲目继续写入。
跨进程恢复同样执行校验，不能只靠内存故障标记；无法证明版本未回退时，未决操作须远端核对。

实施第一步用故障用例验证上述能力，包括“磁盘未写入”和“已写入但调用者观察失败”。若
现有 API 无法可靠区分缺失/损坏、恢复磁盘真值，允许改用最小的加密版本化原子存储；先记录
失败证据与选择依据，再实现。不得为坚持复用而自行解析并依赖未经验证的系统内部缓存协议。
任何迁移都只接收成功解密且验证通过的旧数据，新记录确认完成前保留旧密文，不自动回退旧版本。

存储在专用串行执行器运行。“同步 commit”指等待耐久结果后才推进依赖动作，不指阻塞 UI。
不得持有通话控制锁等待磁盘或网络；存储阻塞时，已知且已授权的本地闭麦/挂断入口仍可响应。

读取结果区分 MISSING、READY、UNAVAILABLE、UNREADABLE、UNSUPPORTED_VERSION。
只有确认不存在已保存数据才进入首次初始化；无法可靠区分暂时/永久错误时保持 UNAVAILABLE。
已有密文但密钥缺失不能创建替代密钥；任何失败都保留原始密文。
未来版本不能被旧版登录或设置保存静默覆盖。

已有无版本格式作为 legacy v0：成功解密、验证后可通过同一提交路径添加版本字段，保留
既有登录、读卡器凭据、短信未知结果；失败不回落空配置，不回退到更旧操作记录。
显式重置须说明会丢失本地恢复信息、不能证明远端通话结束；存在未决通话时优先引导核对。
已知精确身份的安全挂断不因本地存储故障被禁止；仍须通过服务端授权，不自动重复挂断或
生成新的终止操作身份。远端结果与本地持久化是两个事实：收到权威终态即可如实展示远端
已结束；若保存失败，保留耐久未决记录和内存证据，禁止新付费操作越过存储门禁。再次进程
死亡后重新查询，不能假定上次内存证据幸存。只有终态耐久成功才退休未决记录。

## 4. 读卡器观察

复用 ReaderHub 所有权检查，引入最小不可变观察：owner epoch、扫描状态、观察时间、拓扑。
共享启停、hub 替换、失效/超时统一更新这一个状态，页面、握手及周期健康报告只读它。
不可变必须落实为完整快照/防御性深拷贝，不向 UI 或发送线程暴露仍可修改的共享 JSONObject。

停用先失效旧 epoch/观察，再关闭旧连接和 hub。启用创建新 owner，先报告 recovering，
不携带旧就绪卡片；当前 owner 扫描完成后才能报告新 generation/身份。
网络重连可复用同一个仍有效的 hub，但必须验证观察的新鲜度；过期或所有权不符先 recovering。

旧扫描完成、旧连接回调和旧扫描 finally 不得发布新 owner 的状态、关闭其设备或清除其
scanPending。复用现有串行 readerIO，不再创建额外扫描守护线程或加快轮询。
AKA 前的新鲜身份读取、插卡代际校验、拒绝未知卡保持不变。

## 5. 通话耐久记录与控制恢复

### 最小记录

保存 schema、记录 revision、服务器身份、经验证的账户绑定、transport、line/card ID、
原 call/incoming-event ID、start/end operation ID、已获得的 session ID、蜂窝 occurrence/
generation 和最后耐久阶段。不得用新生成的 CallPlan 构造器重建原操作 ID。
绑定不能仅依赖可变的界面用户名或原 session token；重新登录后须由 Core 重新核验主体。
记录继续加密，不保存音频、密码或无关消息内容，不进入诊断导出/云备份。

### 写入顺序

```text
保存 PREPARING（原始身份）
-> 申请原媒体租约
-> 保存 session ID
-> 原有音频准备/canary
-> 保存 START_MAY_HAVE_RUN
-> 仅一次 start/answer
-> 确认后保存 ACTIVE
```

### 唯一状态转换所有者

复用现有通话 owner，每个异步结果按记录 ID、账户 epoch、预期 revision 和允许阶段条件更新。
串行写盘不替代状态转换校验。先保留转换所有权，锁外执行 I/O，返回时重新校验；不持锁
等待磁盘/网络，不创建第二个 CallCoordinator。

| 并发事件 | 确定行为 |
|---|---|
| 持久化完成、准备派发 start/answer | 再核对当前 admission、身份及取消标记；取消已生效则零派发 |
| 用户在派发前请求挂断 | 取消尚未执行的 continuation，停止本地音频，处理原准备资源 |
| 派发可能已发生后取消 HTTP | 仅视为客户端取消，不能证明服务端未执行；进入精确核对 |
| ending 阶段收到迟到 start 成功 | 作为原请求证据，不写回正常 ACTIVE、不重新开麦，继续终止核对 |
| 终态记录退休后收到旧回调 | 不复活记录；旧回调只可提供与原记录匹配的诊断信息 |
| 退出、显式重置或账户替换后旧回调到达 | 不写入新账户配置，不重建旧凭据，不接管新通话 |

取消与实际派发在同一 owner 下具有明确的先后裁决；派发获准后即按可能已执行处理。
新增可控制交错的反例测试，不用 sleep 碰运气复现竞态。

任一步持久化失败，禁止进入后续付费请求；已有精确准备资源可走既有清理接口。
请求送达前后丢失响应均保持可能已执行，不通过重拨查结果。
租约已分配但响应未保存：优先按原 owner/call 查询；若现有接口不能可靠定位，保持未知，
由既有准备租约过期机制回收。不新增租约冒充恢复，不把查不到视为通话结束。

阶段不能一律归为“未知通话”：只有记录是最新可信耐久版本、没有回退/格式疑点，且所有
start/answer 路径都受写前门禁约束时，PREPARING 才能表明本客户端未跨过付费派发门禁。
此时显示“未发起通话，正在清理准备资源”，不是“可能正在计费”；准备租约是否仍占用须
按原门禁处理。START_MAY_HAVE_RUN 及之后未确证结果保持通话未知。存储真值不可信时
不得利用旧 PREPARING 解除风险门禁；不使用本地时间到期自动把未知改为结束。

进程启动先加载未决记录并进入恢复卡片，阻止该 App 开新通话。只恢复状态查询/授权挂断，
不自动开麦、申请新媒体或发送 start/answer。同进程的现有同租约媒体 resume 不改变。
本地闭麦和释放本地音频无需等待远端挂断成功；两种状态必须分开显示。

### 查询契约

先完成以下双通道矩阵，再实现依赖它的恢复 controller/UI。每格必须关联实际源文件、
接口/字段和对应测试，记录“可复用/需窄补充/现有证据不足”，不得凭设计填成已支持。

| 待核对内容 | VoWiFi 来源边界 | 蜂窝来源边界 |
|---|---|---|
| 原所有者与重新登录授权 | Core/Provider call 与媒体 owner，核实主体是否跨 session 稳定 | cellularmedia session.subject 与浏览器认证映射 |
| 精确定位键 | 原 call/operation、line/card 与媒体 session | 原 session/operation、line/card 与 occurrence/generation |
| Core/Provider 重启后证据 | 操作回执/活动状态哪些持久，哪些仅内存 | session、Agent 回执和历史记录各自是否仍权威 |
| 未派发、活动、终态证明 | 实际 typed result，禁止套用蜂窝字段 | terminal_confirmed 及其底层确证来源 |
| 原 end operation 重试 | 是推进终止、查询现况还是仅重放旧响应 | 同一 operation 对未确认终止能否继续推进 |

以上是检查位置与问题，不是已核实答案。不能仅凭相同 username、operation ID 或公共 active
快照宣称恢复可授权。若重登录无法安全接回原 owner，先保持未知并提供现有授权管理入口，
不得扩大权限。只有新契约及测试支持后才能承诺原 App 内的完整恢复。

实施前核对现有 operation/status、VoWiFi call、蜂窝 lease/control 查询能否满足恢复需求。
足够则直接复用；确有缺口才补一个窄只读接口，不先规定新增 endpoint 或存储系统。
服务端核对登录主体、服务器、transport、原 line/card/call/session 及必要代际；查询不分配
租约、不迁移所有权、不续命、不执行挂断。所有者专有信息不能进入共享 mobile 缓存。

| 权威结果 | 客户端行为 |
|---|---|
| 原通话仍活动且允许控制 | 展示原通话和挂断，保持麦克风关闭 |
| 请求可能执行、结果不明 | 展示未知和核对入口，不新拨号 |
| 正在结束但未确认 | 保留记录，显示结束未确认 |
| 精确对象的权威终态 | 先耐久保存终态，再退休未决记录 |
| 网络失败、404、缺行、Core 状态丢失 | 保持未知；不能以缺失代替终态 |
| 登录过期 | 保留记录，提示同账户登录后重新授权 |
| 身份冲突或非原所有者 | 不接管/挂断其他通话，显示冲突 |

当前线路关闭或换卡不能误伤另一通话，也不能仅凭当前 SIM 不同就抹去旧通话记录。
只有既有服务端能确认原所有权时，才保留旧通话的终止路径；不为恢复放松身份门禁。
旧 APK 没有耐久记录的通话不保证可恢复，不从公共 active 快照臆造所有权。
证据永久不足时进入“需人工核对”，保留记录并指出缺少的事实，提供已有网关管理入口和
脱敏详情。若管理端也无法安全核对，如实说明限制，不新增“忽略并视为已挂断”按钮；重置
不能作为恢复闭环。新的查询接口也不能凭空恢复已丢失的服务端证据。

### 统一终态

正常挂断和恢复挂断共享终态分类，保留同一个 end operation ID。
蜂窝 HTTP 200 且 terminal_confirmed=false 仍为未确认；缺该字段不能默认为 true。
VoWiFi 按现有精确 call/operation 的实际终态契约判断，不机械套用蜂窝字段。
媒体 WebSocket 正常关闭、音频停止、DELETE lease 成功、一般 404 都不能独立证明运营商通话结束。
挂断可能已执行但回执丢失时先查询；只有接口具备原 operation 的幂等保证且用户明确重试，
才允许用相同 end operation 重试。不得新增自动重试循环。

## 6. 集中验证

仅通过 GitHub workflow 执行构建、测试和 APK 验证，不使用生产设备或收费业务。
先固化旧代码反例，再验证整改代码；不能以 helper 单测代替整条恢复流程。
整批交付不意味着最后才思考验证：实施中持续核对契约并编写反例，只在影响方案成立的
基础问题上安排有明确目的的有限 CI 验证；不按单方法创建临时提交、推送或 workflow。
最终完整候选集中执行整套验证，保持一个交付提交，不以反复构建代替实质进展。

| 场景 | 必须证明 |
|---|---|
| 读取/密钥/解密/版本故障 | 原密文不变、不造新密钥、不自动初始化或覆盖 |
| 并发设置/登录/SMS/通话写入 | 不丢最新记录；写失败阻断新付费提交但不隐藏已知挂断 |
| 共享停用、换卡、再启用 | 握手抢先时首报 recovering，新扫描后才 ready |
| 旧扫描/连接回调晚到 | 不改变新 owner、拓扑或 pending 标记 |
| 租约与 start 各边界杀进程 | 原身份保留；同一逻辑通话 start/answer 总发送次数至多一次 |
| 正常挂断与恢复挂断 | false/404/超时/媒体关闭不误报终态，确证终态才退休记录 |
| 服务端重启与身份冲突 | 不接管其他账户/服务器/卡片/occurrence 的通话 |
| 兼容旧存储与 UI | 登录、SMS 未知记录保留；错误和恢复卡片具有真实可用按钮 |
| 容器损坏/假失败写入/跨进程重读 | 不误认首次安装，不通过内存缓存解锁写入，旧版记录不伪装最新 |
| 派发前取消、结束后迟到成功、账户替换后旧回调 | 零额外派发、不复活 ACTIVE、不覆盖新账户 |
| 远端终态后本地写失败 | 展示远端已结束和保存失败两个事实，无额外挂断、无提前删除 |
| 确认框打开期间线路消失/换卡 | 零派发、保留号码/草稿、明确要求重选，不切到第一条线路 |

真实进程死亡测试的控制器和合成服务端必须在 App 进程之外。保留合成远端通话，强制
结束 App 后重启，核对 PID 变化、原身份和服务端请求计数。Activity 重建不算进程死亡。
同时核对 start/answer 入口计数和合成付费执行者计数，不能只凭页面标签或单侧请求日志判定无重复。
force-stop 后用户重开单独测试，不声称能绕过 Android 的强制停止。
API 28/35 覆盖恢复场景；API 36 能力可用时补当前 target 行为，不能替代兼容性覆盖。

整合场景：start 结果未知 -> 杀进程 -> 第一次读取失败 -> 原文保留且零重拨 -> Retry
读取成功 -> 原通话核对 -> 用户挂断 -> 确认终态 -> 退休记录。
同批执行 Android lint/unit/instrumentation、涉及 Core 的集成/race、现有 Provider/WebUI
回归及真实签名 APK 安装启动。保留失败及跳过原因，发布报告逐项关联精确提交和产物哈希。

## 7. 发布与完成标准

测试通过不等于生产验收。只发布替换预览 APK，不自动合并 PR、升级生产或宣称真实通话通过。
核验旧新证书和 package/version：签名不兼容就明确仅支持新安装，不能声称保留数据升级，
更不能要求带着未解决通话记录卸载。长期 owner 签名另按授权配置，不在源码或日志保存私钥。

三个原缺陷加正常挂断终态误判均有反例和修后证据，才将账本对应项更新为已实现/自动验证；
硬件、运营商、后台送达和耗电仍保留各自未验边界。原有历史验收不被本批清零。

## 8. 作者自审

本节是方案自审，不是独立审计，也不是运行测试的结果。

| 自审问题 | 已收敛的决定 |
|---|---|
| 是否为修复扩大存储架构？ | 不默认迁移文件/数据库，复用现有加密存储并统一更新入口 |
| 是否遗漏非恢复挂断路径？ | 正常挂断、恢复挂断及媒体关闭均纳入同一终态分类 |
| 是否把进程恢复等同自动重拨/开麦？ | 只恢复控制；请求身份先持久化，媒体恢复不跨进程自动执行 |
| 是否把缺失证据当作已结束？ | 404、Core 重启和公共快照缺失均保留未知 |
| 是否可能越权控制旧 SIM 的新通话？ | 依赖服务端原所有权/代际授权，不放松当前身份门禁 |
| 是否把每层改动拆成微提交？ | 跨层一次完成、集中验证、一个完整交付提交 |
| 是否把模拟器当作实卡/生产验收？ | 明确合成服务端边界，不拨号、不变更 SIM、不部署 |
| 是否只有后台方案、没有用户需求？ | 第 1 节需求表区分用户指令、PR 基线和本方案设计，逐项限定范围 |
| 页面是否交给实现者临时发挥？ | 第 1A 节固定五页布局、公共组件、线框、状态/按钮契约及实际点击验收 |
| 后台刷新是否破坏用户输入和选择？ | 按稳定身份增量更新，保留表单、选项、滚动与跨页通话控制 |
| 优化 UI 是否变成另一次重写？ | 复用原生页面和系统组件，只补主流程布局与恢复交互，不新增业务页面 |

第二轮自审结论：总体方案保留；先执行存储基础验证与双通道契约核对，再进入依赖其结果的
客户端实现。它们是前置工程任务，不是默认要求用户重新决定产品方向。未完成前不宣称方案
已经具备闭环恢复能力。实施前从 PR 最新代码确认查询复用、主体绑定和各 transport 的终态契约；若与基线不同，
先更新本方案对应小节，不能照旧行号重复修复。签名是否连续需实际证书证据，不能靠文档推断。

第二轮采纳：真实缺失/写失败恢复、UI 线程隔离、取消与迟到结果、准备阶段分类、人工核对出口、
远端/本地双状态、不可变读卡器观察、确认框固定身份。未采纳高频临时 CI/微提交，也未预定新数据库。

## 9. 本次实现与待评审边界

本次用户要求先提交 PR，评审后再合并和测试。因此本批不运行构建、CI、模拟器或实机测试，
不发布 APK、不部署、不产生收费操作。测试代码随 PR 交付，不标为已通过。开发计划不等于
所有交互或故障注入均已验收；特别是外部控制器杀进程、真实点击矩阵仍待执行和补全证据。

本批具体实现：
- ConfigStore 使用进程级互斥更新和 Keystore 加密 AtomicFile，按磁盘原文读取而非 preferences
  缓存；旧 XML 严格解析后只读迁移，旧材料保留，新存储所有权标记阻止回退到旧配置。
- 读取/写入错误不清数据，提供异步读取及重试页面；普通配置写入不得覆盖 pending_call。
- ReaderHub 观察失效、连接 epoch、扫描 owner 和 recovering 首报接回现有分享流程。
- CallPlan 原始 ID 耐久保存，RemoteCall 进程恢复只查询/终止，不自动开麦或重发 start。
- 普通挂断/恢复挂断共用精确终态分类；404、false、媒体停止保留未知，保存失败单独显示。
- 底部导航、可点的国际号码键盘、跨页恢复按钮、失效线路保留与提交前身份核对。

已核对的实际服务端边界（PR #7 基线）：
| 契约 | VoWiFi | 蜂窝 |
|---|---|---|
| 原 owner | 浏览器登录与媒体租约；本 App additionally 绑定原 token 的摘要及 origin/pin | cellularmedia session.subject，来自登录 token 派生的 subject |
| 重登录 | 不自动接管旧记录，原绑定不匹配进入网关人工核对 | 新 token 会产生新 subject，原 session 不得接管 |
| 查询 | 复用 /v1/lines/{id}/vowifi/status，仅匹配原 active_call | 复用 /v1/lines/{id}/cellular/calls/status，匹配原 session/call |
| 终态 | 原 end operation、call_id、accepted=true、code=ended 的直接回执 | 原 session_id 且 terminal_confirmed=true 的直接回执 |
| 缺失/重启 | 不能由 active 缺失证明结束，保留人工核对 | session 主要为内存；丢失后不能由404证明结束 |

没有新增扩大鉴权的恢复接口，没有承诺重登录或服务端证据丢失后可自动完成恢复。
原 end ID 的手动再次请求保持原身份，但可能只返回旧回执；未确认不得据此生成新 ID 重试。
这项限制需评审明确，不以客户端按钮或模拟测试隐藏。
