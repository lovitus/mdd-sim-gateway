### 正常自动恢复不是人工恢复的替代品

分别呈现三个状态，不用一个“在线”覆盖全部：网关会话、读卡器共享、当前业务/媒体。
短断网时保留用户意图和表单；网关连接恢复后自动同步当前事实并对原未决通话做一次只读核对。
合并同一故障的在途工作，退避期间可显示下次重试，不创建多个重连循环。
前台恢复/网络变化后可触发一次核对，但每次 UI render 不能发起查询。

会话过期提供“重新登录原网关”动作；登录不得清理未决记录。由于当前 Core subject 按 session
生成，新登录不能无条件获得旧通话控制权。先保留旧身份和证据，在新会话下只提供实际已授权
的核对操作；不存在授权接续能力时不伪造“可挂断”。普通读卡器/消息/目录恢复不应被旧通话
未知状态全部锁死。旧通话未知只阻止冲突的新通话，短信仍按自己的耐久和权限门禁执行。
不能通过无限期禁止重新登录、要求卸载或清空配置让用户解困。
自动允许既有授权范围内的连接重建、会话续期、读卡器重新登记/健康上报、状态同步、原操作
只读核对及有效窗口内的同租约媒体恢复。不自动新建或重发start/answer/SMS/DTMF，不跨进程
开麦、不自动重试挂断、不改变用户关闭意图。“无付费动作重试”不等于网络流量免费，也不
代表已有通话在断网期间已停止计费。

自动恢复结果：已恢复 / 重试中 / 需要登录 / 需要设备授权 / 需要网关核对。最后一项必须给
缺失证据类别、实际管理入口和可执行操作，不将普通网络超时一律升级成人工问题。
服务端确已永久丢失证据时不承诺自动闭环，不用超时或用户点击“我知道了”伪造已结束。

### 页面主流程收口

- 首页：网关连接、保持可用、读卡器共享、待处理事件；只有需要处理的异常显示行动入口。
- 通话：服务端线路名称+实际电话号码+卡尾号，按真实能力选择通道；明确当前通话与未决记录；
  来电在任意页有接听/拒接入口，锁屏通知点击能回到精确来电而不是无关首页。
- 短信：按线路和对端查看会话/记录、发送状态及时间，返回后保留输入；新收到消息与历史
  同步分开，不能重连后把旧消息再次全部通知；未知提交保留查状态入口而非默认重发。
- 读卡器：列出未授权设备、已识别卡和真实不可用原因；权限动作对应具体设备；共享关闭
  与连接中断分别显示，不把恢复过程中的旧卡身份当作当前就绪。
- 设置：网关、登录/证书、通知权限、系统电池设置、版本、脱敏诊断；错误信息内提供跳转。
  存储读取失败必须有重试，账号会话失效必须能重新认证，不能形成相互禁止操作的死循环。

复用下方详细线框、组件和状态表；新增设计不是重新换框架。页面成功必须对应真实领域结果，
不能以 UI 可点击或接口返回200代替注册、接听、送达、挂断和音频验收。

R1授权核对不得放宽为“同账户能按客户端提供的call_id随便接管”。必须复用或补充服务端
可信的原操作关联/权限和终态证据，按transport、原line/card/occurrence核对；只在被授权范围
执行只读核对或终止，禁止产生新通话。若无法恢复已丢失的证据，保留未知并准确限制相关
通话；同时允许登录和其他无冲突业务。设计不能承诺历史证据彻底丢失也必然自动解除。
只读核对不替代终止控制：原通话仍活动时，须提供经服务端可信关联授权的原通话终止路径，
或已经验证可执行的管理端处理路径及终态回读；仅能查询不能结束不算恢复闭环。
当前App只有一个通话owner，“冲突新通话”包括该App新建的服务器通话；不因此新增多通话能力，
也不阻断独立短信、读卡器、登录及只读页面。

恢复时限从App获得执行机会且网络恢复稳定时起算；60秒目标要求Core可达、凭据有效且
设备权限/硬件可用。180秒内报告恢复结果或实际可观察的阻塞层级，无法定位就明确未知；
IMS等待单列，不计入客户端完成承诺，网络抖动不能无限重置故障报告时钟。
8小时锁屏测试须记录设备/系统/电池优化设置和断连区间，不能只凭期末在线声称全程可用。
8小时是用户批准后的测试任务时长，不是agent阻塞等待时长；不突破单次600秒等待，不用
后台agent或自动续接轮询。由批准的测试任务留证据，完成后一次收集。耗电对照数据形成后
再给出同条件差异和可接受性判断，不能仅凭采样已执行就宣称省电达标。

测试框架。官方Maven发布元数据已核对到OkHttp5.5.0；本批所需WebSocket升级与延迟响应

## 1. 完整交付范围

### 用户需求与来源

用户要求的是能实际使用的原生 Android 客户端，不是只有后台连接或诊断状态的演示程序。
本轮用户明确要求：开发计划记录具体需求，并给出优雅、可交互的页面设计，防止后台实现脱离操作。
以下功能目标来自 PR #7 的 Android 决策和交付材料，是本次评审的产品基线；不是本轮新增授权。
下面的布局、按钮和文案是本方案提出的设计，不冒称用户逐项指定。

| 需求 | 用户能够完成的事情 | 本批交付边界 |
|---|---|---|
| 方便接入网关 | 登录、扫码/粘贴设置、自签证书指纹确认；再次打开不反复配置 | 保留现有入口；补存储失败和会话过期的明确恢复入口 |

### 用户主流程完成条件

用户再次打开 App 时，应首先看到自己仍在处理的事情：正常则进入上次页面；有未决通话则
看到恢复入口；存储暂时读不到则保留原配置并提供重试。不能一律回到像首次安装一样的空白登录页。
关闭共享后换卡，再打开共享，应看到重新检测，随后只出现新卡；未知通话不能凭空消失。
发出挂断后，界面必须区分本地声音停止、远端结束未确认、远端已确认结束。

一次修复同一恢复主流程的四个缺口：

1. 读取配置失败不得删除配置、凭据和未知操作记录。
2. 读卡器重新共享/重新连接不得把过期拓扑当作当前就绪状态。
3. App 进程死亡后，恢复原未决通话的核对和授权挂断入口，不重新拨号。
4. 正常挂断与恢复挂断统一终态判断，不能把 HTTP 200、404 或媒体关闭当作已确认结束。

存储、读卡器、Android/Core 接口、页面和回归属于同一整改批次。先全部实现，再集中验证，
最后一个完整交付批次更新 PR #8；不按单类、单接口、单测试拆分微提交。PR 保持 draft 待评审。

不在范围：替换整套 Android UI 框架、恢复 VPCD、自动重拨/SMS、跨进程自动开麦、生产部署、真实
收费业务、SIM 变更、eSIM 删除、桌面 4G 开关调整、FCM 接入或全天候后台送达承诺。
真实读卡器兼容性、Doze/耗电、运营商验收与长期签名是独立事项，不冒称随本批完成。

## 1A. 页面与交互设计

### 布局与复用组件

沿用原生五页：首页、通话、短信、读卡器、设置。底部导航使用图标加短标签，不用五个
挤在顶部的普通命令按钮；保留现有 Activity/Service 边界，不为此引入新 UI 框架。
顶部只保留页面标题、网关简称和连接状态。正文采用列表、分组标题和细分隔线，不把每段内容
都放进卡片。活动通话是需要持续可见的独立控制区域，不随切换 tab 销毁。

统一复用：连接状态条、线路选择器、状态行、当前通话条、错误恢复面板、确认对话框。
中文为完整可用语言，沿用系统语言/现有资源选择；原始错误码收进可展开详情，不把英文异常堆在首页。
状态不能仅靠红绿区分：文字加图标，明确连接、设备、IMS、通话分别是什么状态。
图标使用项目可用的标准 Android 图标资源，提供无障碍名称；不手绘含糊图标或引入整套新设计依赖。

布局约束：竖屏320dp 窄屏、200% 字体、系统栏和软键盘下都可操作；横屏问题延期。控件触控目标至少
48dp；文本允许换行但不得遮挡按钮。拨号键盘稳定三列，导航和底部操作不被键盘盖住。
后台更新按稳定 ID 更新行，不重建整个页面，不重置所选线路、通道、号码、短信草稿或滚动位置。
所选线路消失、换卡或不可用时，保留原选择并标记不可用，要求用户重新选择；禁止自动选择
第一条剩余线路或切换通道。确认框捕获不可变的线路、卡片、通道、号码及必要 occurrence，
提交前重新校验同一意图。期间身份变化则零派发、保留输入，显示“线路身份已变化，请重新选择”。

## 3. 存储实现

### 最小改动与单一所有者

优先验证现有加密 SharedPreferences 是否满足下述故障契约；不预先认定它必然足够。
建立应用级唯一存储入口，Activity/Service
都通过该入口更新字段，不能各自读整份 JSON 后覆盖其他并发写入。
现有 synchronized 仅保护单个 ConfigStore 实例，不等于应用级串行化。

每次更新基于最新已提交记录生成副本，串行加密并同步 commit；确认成功后才发布内存新状态。
写失败不发送新的 start/answer/SMS，不用未提交内存状态冒充耐久记录。
若底层写失败可能影响内存缓存，进入存储故障状态，禁止随后基于该缓存继续覆盖。
不为本批预先改用新文件、数据库或引入通用事务框架。

### 真实缺失、写入不确定及恢复门槛

SharedPreferences 部分容器读取/解析失败可能返回空映射；`getString` 默认空值、contains=false
或重新创建包装类都不能证明首次安装。必须在跨进程测试中覆盖实际 preferences 容器损坏，
而不只是合法 XML 中的坏密文。首次初始化须有可靠的存储缺失证据；已有容器/备份或读取
不确定时保持故障态，不写入空配置。不能以同一个可能丢失的 preferences 标记自证不存在。

commit 返回 false、中断或进程死亡时，不假定旧值或尝试值已耐久。当前进程锁定写入门禁，
停止设置、登录和操作记录的后续覆盖，保留原材料与在途记录身份。不得通过同进程缓存读回
解除门禁。解除须先确保旧写入不再在途，再从可靠磁盘读取验证加密完整性、schema、记录
revision 和阶段一致性；若不能证明得到的是可信记录，保持故障，不允许盲目继续写入。
跨进程恢复同样执行校验，不能只靠内存故障标记；无法证明版本未回退时，未决操作须远端核对。

实施第一步用故障用例验证上述能力，包括“磁盘未写入”和“已写入但调用者观察失败”。若
现有 API 无法可靠区分缺失/损坏、恢复磁盘真值，允许改用最小的加密版本化原子存储；先记录
失败证据与选择依据，再实现。不得为坚持复用而自行解析并依赖未经验证的系统内部缓存协议。
任何迁移都只接收成功解密且验证通过的旧数据，新记录确认完成前保留旧密文，不自动回退旧版本。

存储在专用串行执行器运行。“同步 commit”指等待耐久结果后才推进依赖动作，不指阻塞 UI。
不得持有通话控制锁等待磁盘或网络；存储阻塞时，已知且已授权的本地闭麦/挂断入口仍可响应。

### 提交成功判定与迁移顺序（R8）

AtomicFile的finishWrite正常返回不是充分成功条件。存储层向调用者返回明确的COMMITTED或
UNKNOWN/FAILED结果，成功必须绑定本次记录身份、revision和内容摘要；加密成功、缓存命中、
方法未抛错均不能单独放行start/answer/SMS。保留现有显式文件sync和解密读回，但它们不能
替代发布结果及所声明耐久边界的验证。文件同步、发布或结果校验失败均关闭付费派发门禁。

实现必须说明采用API能否可靠传播sync/close/rename失败；若不能，就增加最小可检测封装，
不能假定平台内部日志等于调用失败。区分普通App进程死亡和设备掉电/文件系统崩溃的保证，
说明目录项发布的同步策略；未经验证不得承诺掉电后绝不回退。成功证据须对应本次revision，
而不是恰好读到了某个可解密的旧文件。不要因此引入另一套通话数据库。

独立.owned迁移标记与主数据不是一个原子事务，实施必须满足以下恢复表，并以故障注入证明：

| 崩溃时磁盘形态 | 恢复行为 |
|---|---|
| 只有完整可验证旧XML，无新存储所有权证据 | 可只读验证旧格式并准备迁移；损坏不能当首次安装 |
| 所有权标记已发布，主数据未完整发布 | 保留全部材料，进入迁移未完成；不回退旧XML派发，不覆盖为空配置 |
| 临时新文件存在但主数据未发布 | 不把临时数据当已提交；核对迁移阶段，不新初始化 |
| 新主数据完整且标记一致 | 核对schema/revision/完整性后使用新数据；旧XML仅作恢复材料 |
| 新数据存在但标记缺失/不一致 | 不直接认定提交成功，先核对并修复一致性；未确证不派发 |
| 迁移后新数据损坏，旧XML仍完整 | 不自动回退旧身份/旧操作阶段，保留材料并显示读取故障 |

标记发布前后的同步及主文件发布顺序必须显式实现，不把以上表格当作磁盘已经提供的保证。
故障测试覆盖每个边界，记录实际可检测结果；不能仅捕获包装函数自行抛出的异常就标通过。

读取结果区分 MISSING、READY、UNAVAILABLE、UNREADABLE、UNSUPPORTED_VERSION。
只有确认不存在已保存数据才进入首次初始化；无法可靠区分暂时/永久错误时保持 UNAVAILABLE。
已有密文但密钥缺失不能创建替代密钥；任何失败都保留原始密文。
未来版本不能被旧版登录或设置保存静默覆盖。

已有无版本格式作为 legacy v0：成功解密、验证后可通过同一提交路径添加版本字段，保留
既有登录、读卡器凭据、短信未知结果；失败不回落空配置，不回退到更旧操作记录。
显式重置须说明会丢失本地恢复信息、不能证明远端通话结束；存在未决通话时优先引导核对。
已知精确身份的安全挂断不因本地存储故障被禁止；仍须通过服务端授权，不自动重复挂断或
生成新的终止操作身份。远端结果与本地持久化是两个事实：收到权威终态即可如实展示远端
已结束；若保存失败，保留耐久未决记录和内存证据，禁止新付费操作越过存储门禁。再次进程
死亡后重新查询，不能假定上次内存证据幸存。只有终态耐久成功才退休未决记录。

## 4. 读卡器观察

复用 ReaderHub 所有权检查，引入最小不可变观察：owner epoch、扫描状态、观察时间、拓扑。
共享启停、hub 替换、失效/超时统一更新这一个状态，页面、握手及周期健康报告只读它。
不可变必须落实为完整快照/防御性深拷贝，不向 UI 或发送线程暴露仍可修改的共享 JSONObject。

停用先失效旧 epoch/观察，再关闭旧连接和 hub。启用创建新 owner，先报告 recovering，
不携带旧就绪卡片；当前 owner 扫描完成后才能报告新 generation/身份。
网络重连可复用同一个仍有效的 hub，但必须验证观察的新鲜度；过期或所有权不符先 recovering。

旧扫描完成、旧连接回调和旧扫描 finally 不得发布新 owner 的状态、关闭其设备或清除其
scanPending。复用现有串行 readerIO，不再创建额外扫描守护线程或加快轮询。
AKA 前的新鲜身份读取、插卡代际校验、拒绝未知卡保持不变。

## 5. 通话耐久记录与控制恢复

### 最小记录

保存 schema、记录 revision、服务器身份、经验证的账户绑定、transport、line/card ID、
原 call/incoming-event ID、start/end operation ID、已获得的 session ID、蜂窝 occurrence/
generation 和最后耐久阶段。不得用新生成的 CallPlan 构造器重建原操作 ID。
绑定不能仅依赖可变的界面用户名或原 session token；重新登录后须由 Core 重新核验主体。
记录继续加密，不保存音频、密码或无关消息内容，不进入诊断导出/云备份。

### 写入顺序

```text
保存 PREPARING（原始身份）
-> 申请原媒体租约
-> 保存 session ID
-> 原有音频准备/canary
-> 保存 START_MAY_HAVE_RUN
-> 仅一次 start/answer
-> 确认后保存 ACTIVE
```

### 唯一状态转换所有者

复用现有通话 owner，每个异步结果按记录 ID、账户 epoch、预期 revision 和允许阶段条件更新。
串行写盘不替代状态转换校验。先保留转换所有权，锁外执行 I/O，返回时重新校验；不持锁
等待磁盘/网络，不创建第二个 CallCoordinator。

| 并发事件 | 确定行为 |
|---|---|
| 持久化完成、准备派发 start/answer | 再核对当前 admission、身份及取消标记；取消已生效则零派发 |
| 用户在派发前请求挂断 | 取消尚未执行的 continuation，停止本地音频，处理原准备资源 |
| 派发可能已发生后取消 HTTP | 仅视为客户端取消，不能证明服务端未执行；进入精确核对 |
| ending 阶段收到迟到 start 成功 | 作为原请求证据，不写回正常 ACTIVE、不重新开麦，继续终止核对 |
| 终态记录退休后收到旧回调 | 不复活记录；旧回调只可提供与原记录匹配的诊断信息 |
| 退出、显式重置或账户替换后旧回调到达 | 不写入新账户配置，不重建旧凭据，不接管新通话 |

取消与实际派发在同一 owner 下具有明确的先后裁决；派发获准后即按可能已执行处理。
新增可控制交错的反例测试，不用 sleep 碰运气复现竞态。

任一步持久化失败，禁止进入后续付费请求；已有精确准备资源可走既有清理接口。
请求送达前后丢失响应均保持可能已执行，不通过重拨查结果。
租约已分配但响应未保存：优先按原 owner/call 查询；若现有接口不能可靠定位，保持未知，
由既有准备租约过期机制回收。不新增租约冒充恢复，不把查不到视为通话结束。

阶段不能一律归为“未知通话”：只有记录是最新可信耐久版本、没有回退/格式疑点，且所有
start/answer 路径都受写前门禁约束时，PREPARING 才能表明本客户端未跨过付费派发门禁。
此时显示“未发起通话，正在清理准备资源”，不是“可能正在计费”；准备租约是否仍占用须
按原门禁处理。START_MAY_HAVE_RUN 及之后未确证结果保持通话未知。存储真值不可信时
不得利用旧 PREPARING 解除风险门禁；不使用本地时间到期自动把未知改为结束。

进程启动先加载未决记录并进入恢复卡片，阻止该 App 开新通话。只恢复状态查询/授权挂断，
不自动开麦、申请新媒体或发送 start/answer。同进程的现有同租约媒体 resume 不改变。
本地闭麦和释放本地音频无需等待远端挂断成功；两种状态必须分开显示。

### 查询契约

先完成以下双通道矩阵，再实现依赖它的恢复 controller/UI。每格必须关联实际源文件、
接口/字段和对应测试，记录“可复用/需窄补充/现有证据不足”，不得凭设计填成已支持。

| 待核对内容 | VoWiFi 来源边界 | 蜂窝来源边界 |
|---|---|---|
| 原所有者与重新登录授权 | Core/Provider call 与媒体 owner，核实主体是否跨 session 稳定 | cellularmedia session.subject 与浏览器认证映射 |
| 精确定位键 | 原 call/operation、line/card 与媒体 session | 原 session/operation、line/card 与 occurrence/generation |
| Core/Provider 重启后证据 | 操作回执/活动状态哪些持久，哪些仅内存 | session、Agent 回执和历史记录各自是否仍权威 |
| 未派发、活动、终态证明 | 实际 typed result，禁止套用蜂窝字段 | terminal_confirmed 及其底层确证来源 |
| 原 end operation 重试 | 是推进终止、查询现况还是仅重放旧响应 | 同一 operation 对未确认终止能否继续推进 |
| App离线期间自然/保护性终止 | 对方挂断、守卫终止、end回执丢失的精确结果来源、保留期及重启有效性 | 原session/operation/occurrence对应终态来源、保留期及Core/Agent重启有效性 |

以上是检查位置与问题，不是已核实答案。不能仅凭相同 username、operation ID 或公共 active
快照宣称恢复可授权。若重登录无法安全接回原 owner，先保持未知并提供现有授权管理入口，
不得扩大权限。只有新契约及测试支持后才能承诺原 App 内的完整恢复。

实施前核对现有 operation/status、VoWiFi call、蜂窝 lease/control 查询能否满足恢复需求。
足够则直接复用；查询确有缺口才补窄只读接口，不先规定新增 endpoint 或存储系统。
原会话失效后的终止路径另按顶部R1处理：保留精确授权的原通话控制或可执行管理端闭环，
不得因本节只读查询范围而省略该必要控制；不能扩大新session权限。
服务端核对登录主体、服务器、transport、原 line/card/call/session 及必要代际；查询不分配
租约、不迁移所有权、不续命、不执行挂断。所有者专有信息不能进入共享 mobile 缓存。

| 权威结果 | 客户端行为 |
|---|---|
| 原通话仍活动且允许控制 | 展示原通话和挂断，保持麦克风关闭 |
| 请求可能执行、结果不明 | 展示未知和核对入口，不新拨号 |
| 正在结束但未确认 | 保留记录，显示结束未确认 |
| 精确对象的权威终态 | 先耐久保存终态，再退休未决记录 |
| 网络失败、404、缺行、Core 状态丢失 | 保持未知；不能以缺失代替终态 |
| 登录过期 | 保留记录，提示同账户登录后重新授权 |
| 身份冲突或非原所有者 | 不接管/挂断其他通话，显示冲突 |

当前线路关闭或换卡不能误伤另一通话，也不能仅凭当前 SIM 不同就抹去旧通话记录。
只有既有服务端能确认原所有权时，才保留旧通话的终止路径；不为恢复放松身份门禁。
旧 APK 没有耐久记录的通话不保证可恢复，不从公共 active 快照臆造所有权。
证据永久不足时进入“需人工核对”，保留记录并指出缺少的事实，提供已有网关管理入口和
脱敏详情。若管理端也无法安全核对，如实说明限制，不新增“忽略并视为已挂断”按钮；重置
不能作为恢复闭环。新的查询接口也不能凭空恢复已丢失的服务端证据。

### 自然结束与终态留存（R9）

正常的远端挂断不得被归入“证据永久丢失”例外。App不在时对方挂断、已有守卫确认结束，
或者end成功但响应丢失，必须能从现有回执/历史按原身份查回权威终态，不要求再次挂断才能知道结果。
优先复用现有业务存储；若只有活动列表或易失session，就补入最小精确终态记录/查询，而非
新建第二套通话数据库。历史展示的ended字样只有在真实确证来源下才能作为终态，不以媒体断连代替。

实施审阅前填实双通道的来源字段、可信账户关联、保留期限、过期行为及服务端各组件重启后
是否仍有效。客户端据此读取和退休未决记录；不要凭空指定一个未实现的保留期限。会话已过期
时按R1重新认证/授权核对，保留原操作关联，不靠相同用户名或客户端call_id单独授予控制权。
如果证据真的超出保留期或丢失，明确缺口并保留人工处理；普通自然结束必须走可完成的正常流程。

### 统一终态

正常挂断和恢复挂断共享终态分类，保留同一个 end operation ID。
蜂窝 HTTP 200 且 terminal_confirmed=false 仍为未确认；缺该字段不能默认为 true。
VoWiFi 按现有精确 call/operation 的实际终态契约判断，不机械套用蜂窝字段。
媒体 WebSocket 正常关闭、音频停止、DELETE lease 成功、一般 404 都不能独立证明运营商通话结束。
挂断可能已执行但回执丢失时先查询；只有接口具备原 operation 的幂等保证且用户明确重试，
才允许用相同 end operation 重试。不得新增自动重试循环。

同时核对 start/answer 入口计数和合成付费执行者计数，不能只凭页面标签或单侧请求日志判定无重复。
force-stop 后用户重开单独测试，不声称能绕过 Android 的强制停止。
API 28/35 覆盖恢复场景；API 36 能力可用时补当前 target 行为，不能替代兼容性覆盖。

2026-09-23外部控制器实施：复用既有coder/websocket v1.8.15与标准TLS/HTTP，独立Go测试

未决准备按原session清理，已派发按原call/operation/recovery能力只读核对，SMS按原正文查询。

## 7. 发布与完成标准

测试通过不等于生产验收。只发布替换预览 APK，不自动合并 PR、升级生产或宣称真实通话通过。
核验旧新证书和 package/version：签名不兼容就明确仅支持新安装，不能声称保留数据升级，
更不能要求带着未解决通话记录卸载。长期 owner 签名另按授权配置，不在源码或日志保存私钥。

三个原缺陷加正常挂断终态误判均有反例和修后证据，才将账本对应项更新为已实现/自动验证；
硬件、运营商、后台送达和耗电仍保留各自未验边界。原有历史验收不被本批清零。
完整产品实施审阅还须覆盖U1-U7与R1-R11：实际来源填完的双通道矩阵、可判定存储提交、
迁移恢复表、全线路来电/能力契约和多笔短信补收均须有实现及测试源码。测试未执行就标未执行。
自动验证只在授权后对精确候选执行；实机验收保持独立层级。任何旧版计划的评审通过不替代这些条件。

### 音频焦点修复的先行失败清单

在修改实现前，端到端回归必须覆盖：
1. VoWiFi 与蜂窝通话中发生 `AUDIOFOCUS_LOSS_TRANSIENT` 或 `AUDIOFOCUS_LOSS_TRANSIENT_CAN_DUCK`：不关闭 `NativeAudio`、不发送 provider end、不释放原 call owner；UI 明确显示本地音频暂停。
2. 焦点恢复到 `AUDIOFOCUS_GAIN`：清理暂停期间缓存的旧下行帧，原媒体仍连接且音频状态恢复；不创建第二条 lease、不重复 start。
3. 永久 `AUDIOFOCUS_LOSS`：本地媒体失败可见，但不能伪称远端通话已结束或自动发送收费 end；原 pending 身份保留，用户明确挂断仍仅结束原通话一次。
4. 音频已经关闭后迟到的焦点回调不能重连或恢复麦克风；暂停期间不得把新采集帧发送到服务器，也不得播放缓存语音。
5. 暂停/恢复本机 AudioRecord 或 AudioTrack 失败时，只报告本机媒体失败并保留原远端通话身份；不能因设备 API 异常而自动发送 end 或清掉 pending call。
6. 快速 loss→gain 交错时，停止设备导致的迟到 read/write 错误不得杀死已恢复的音频线程；每种方向都应在原 call owner 下恢复，不能创建第二个 lease/start。

验证优先复用 `CallFlowTest` 的真实 UI、音频设备回调和合成网关；不触发运营商通话、SMS 或 SIM/APDU 操作。
